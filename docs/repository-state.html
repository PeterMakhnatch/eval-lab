Functional spine. Incomplete research loop.

Eval Lab is a local-first workbench around Harbor for running agent evaluations, preserving raw evidence, indexing and projecting results, and controlling what may run unattended. Its control and data pipeline works today. Its real-model, judgment, and autonomous-research layers still need integration repair before their outputs should drive decisions.

Scope: local checkout, current GitHub state, live health probes, current catalog and queue, default and excluded test suites, and merged inspection reports.

Maturity: operational foundation

This is more than a scaffold: it can execute free controls end to end and maintain a coherent evidence index. It is not yet a production evaluation platform or a trustworthy unattended scientific loop.

The next move is hardening, not feature expansion.

What the repository is for

The repository is the control and evidence layer around Harbor, not a replacement harness. It answers four questions: what was intended, what ran, what evidence it produced, and what is safe to do next.

Where to go from here

Do not start a new capability wave yet. One short foundation wave can turn the current collection of strong components into a dependable research system.

  1. Make CI cover the repository-owned tests. Add dashboard, calibration, and analysis suites to the gate; repair migrated evidence paths and the stale artifact expectation. Keep benchmark task tests separate because they belong to task containers.
  2. Add the composed free-control smoke. A single deterministic command should prove submit → admission → Harbor → reward → catalog → Parquet and fail on any broken link.
  3. Restore one valid real-model canary. Reconcile Codex authentication with Harbor 0.21, stop after the first repeated auth failure, and require one trajectory containing an actual assistant turn before interpreting scores.
  4. Repair the evidence-dependent layers. Freeze one judge input contract; fix the three dominant criteria; preserve researcher bundles under durable evidence; validate link existence, content hashes, denominators, and trial IDs before appending a discovery.
  5. Resolve shared-state topology. Choose one explicit model for PostgreSQL and Parquet across worktrees: shared derived root, isolated catalogs, or evidence-root-scoped invariants.
  6. Reconcile the human documentation. Update README capability claims, structure map, operating manual attribution, stale handoff headers, and fleet documentation so the repository has one current story.
