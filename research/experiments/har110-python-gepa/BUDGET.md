# HAR-110 budget: time-based formula with per-trial estimates

Status: STAGED + nop qualification only. No paid model call made; no proposer
authorization written; no target spec approved. Policy ceilings:
per_job_cost_ceiling_usd 3, daily_cost_ceiling_usd 20
(policy/standing-approvals.yaml). The worst-case per-trial estimate ($1.85) is
< $3, so no per-job cap raise is needed for the staged plan. Trials run on
Daytona (base spec `environment: daytona`), and the student is the self-hosted
distill (tokens priced at $0), so each trial has two spend types, reported
separately: GPU/server time (metered Modal) and sandbox time (metered
Daytona). The per-trial model-spend ceiling (`cost_limit_usd` $0.01) is
nominal and never trips; spend is bounded by the 3600 s agent timeout plus the
proxy request/token ceilings (120 requests / 2.5M input / 131072 output).

## Formula

```
total_target_trials  <= max_target_attempts                            (= 22, enforced by AggregateBudget)
                     = 6 baseline (seed x 6 dev) + 10 upstream search + 6 selection re-evals
total_proposer_calls <= max_proposer_requests                           (= 4, 1 request each, no retries)
total_heldout        = heldout_tasks x arms x attempts                  (= 4 x 2 x 1 = 8)

C_STUDENT_TRIAL = mimo_selfhosted_trial_cost_usd(trial_hours, c, sandbox_usd)
                = 2.8149 x trial_h / c + sandbox_usd   (+ ~$0.40 per warm period, counted separately)
$search  = total_target_trials x C_STUDENT_TRIAL + total_proposer_calls x C_PROPOSER_CALL
$heldout = 8 x C_STUDENT_TRIAL
```

Model (GPU/server) and sandbox lines are always reported separately; missing
inputs are `None` with a reason, never 0 (see Unknowns).

## Trial profile (why ~10-15 min, not 3600 s)

The route caps input at 2.5M tokens with max_requests 120. HAR-104 proof
trials on these tasks hit the 2.5M-token ceiling in ~10-15 min and stop
there; the 3600 s agent timeout is a backstop, not the usual length. Budget
math below uses wall ~12.5 min (0.208 h) as the expected case and the full
3600 s only for the worst-case spec estimate.

## Per-trial costs (base spec `student-terminus2-selfhosted-python.json`)

- Model/GPU line: `mimo_selfhosted_trial_cost_usd` server share only (tokens $0).
  Expected at c=2: 2.8149 x 0.208 / 2 = **~$0.29**; backstop (full 3600 s
  agent timeout at c=2): 2.8149 / 2 = **$1.41**.
- Sandbox line: code $0.23094/h. Expected (~15 min incl. setup): **~$0.058**;
  worst case (agent 3600 s + verifier 2100 s + 900 s margin = 6600 s):
  **$0.42**.
- Warm line: **~$0.40 per warm period**, counted separately (count: None, see
  Unknowns).
- Spec estimate (worst case, carried as `est_cost_usd`): 0.01 + 0.42 + 1.41
  = **$1.85** (= HAR-81 `stage.py worst_usd` for this profile at c=2; computed
  with the real `estimate_cost_usd` + `mimo_selfhosted_trial_cost_usd`
  functions, ceiling-rounded).
- THE c=1 COUNTERFACTUAL: the same formula at c=1 gives **$3.25**, ABOVE the
  $3.00 per-job ceiling. The $1.85 estimate is honest ONLY if live waves share
  the Modal server across >= 2 concurrent trials. Never tick a lone trial and
  call it covered: either tick >= 2 together or re-estimate first (see Waves).
- `C_PROPOSER_CALL`: one direct GLM-5.3 call on the Z.ai standard API at
  LiteLLM's $1.40/M in + $4.40/M out; the measured first prompt cost
  **$0.059**. `max_proposer_cost_usd` $0.20 is checked before each call, so
  the fourth call can overshoot it: worst case ~4 x $0.08 = $0.32 <= $1.00.
- Search Modal/server: ~16 new trials (6 baseline + 10 upstream; selection
  re-evals mostly hit retained receipts) x $0.29 = **~$4.7 expected** (fits
  ~$5); hard-cap exposure 22 x $0.29 = $6.4 expected-profile, 22 x $1.41 =
  $31.0 backstop-profile (plus sandbox + warms).
- Search sandbox: ~16-22 trials x $0.058 = **~$0.9-1.3 expected**.
- Held-out: 8 trials x $0.29 = **~$2.3** server + ~$0.5 sandbox expected;
  worst-case catalog 8 x $1.85 = $14.80.
- The $20 daily ceiling covers expected sums but not worst-case catalog sums
  (22 x $1.85 = $40.70), and neither sum includes warms: dispatch in waves
  (as in HAR-81/HAR-85), compare measured spend against these lines before
  the next wave, and stop the Modal app between phases. The queue's $20/day
  ceiling adds each spec's $1.85 estimate to catalog spend but never sees the
  Modal server bill -- the operator's controls for it are `modal billing
  report` and stopping the app.

## Qualification (this staging; cap $0.20, nop on Daytona)

6 nop trials x ~2.5 min x $0.23094/h = **~$0.06 expected**, all sandbox (no
server, no model). Cap $0.20 leaves ~3x headroom for slow image pulls. See

- Post-ceiling trial length: `None` -- the 10-15 min profile comes from
  HAR-104 proof trials on this exact route; longer loops hit the 3600 s
  backstop instead. The $1.85 spec estimate covers everything up to the

## Options B/C deltas (proposer-options.json)

- B: 8 reflection calls, proposer cap $0.40 → +4 x C_PROPOSER_CALL.
- C: 2 reflection calls, proposer cap $0.10 → -2 x C_PROPOSER_CALL.
- Every option sums to <= $1.00 (requests x $0.05 per-call ceiling).
- Student-route swap: done (HAR-104 route). Any future route change replaces
  `base-specs/student-terminus2-selfhosted-python.json` and recomputes this
  file with the new route's C_STUDENT_TRIAL.

## Approval rounds

- Baseline gate and final selection loop park EVERY example before halting
  (`src/evallab/gepa_optimizer/workflow.py` `_evaluate_allowing_pending`):
  baseline = 1 round (6 specs), selection = 1 round.
- In-engine search still halts per novel batch: worst case 10 rounds, typical
  a handful. Worst case ≈ 12 rounds total; typical ≈ 5-8. Hard cap unchanged:
  `AggregateBudget` `max_target_attempts: 22` distinct target submissions.

## Waves (operator discipline for the c=2 estimate)

- Tick the 6 baseline specs TOGETHER (`--parallel` / one tick covering all
  six) so the Modal server is shared (c >= 2) from the first wave.
- Search rounds park smaller novel batches; tick each round's batch together,
  never a lone spec. If a round parks exactly 1 spec, pair it with the next
  round's batch or accept that its server share is ~2x the estimate and log it.
- In-engine minibatches were deliberately NOT parallelized (same race as
  HAR-85: `_ensure_candidate_stored` `exists()`-then-`open("x")` fails
  concurrent same-candidate stores; see HAR-85 BUDGET.md). Parallelism lives
  at the tick layer, not in the engine.
