# LS-ACTIONS: decision-window evidence study blocked

**Question.** Does adding reasoning-free, action-bearing evidence to the installed reader's window improve cheat recall without increasing clean false flags above 3%?

**What ran.** We inspected the current `origin/main` implementation at `27ddb12f1c4f90eac5661997526f094a1d405db2`, the earlier replay and visibility receipts, and set up a separate locked worktree environment. We did not join labels, construct a window sample, implement an extractor, or call a study adjudicator. The preregistration is `PREREG.md` (recorded 2026-10-29T23:55:01Z, SHA-256 `aa046bac889656ad35683fab5f1a274939a998599fa4f842aa144b4a4ba39052`). The seeded sampling rule is recorded, but no sample was drawn.

**Why blocked.** The available labels do not establish the requested ground truth for actual reader decision windows. CheatBench's 75 positive and 75 clean DEV labels in the prior replay are run-level and have no onset; all 150 have no step timestamps (local replay README, sections “What the labels mean” and “Timestamp coverage”). A positive run does not establish that a particular early window shows cheating. The replay synthesizes step times for untimed traces and only attaches a replay window when the clock is observed (`live_supervisor_replay.py:120-136, 325, 365-368, 487-501`); it cannot recover the actual historical decision window from those timestamps. Goodfire has passage-step annotations, but their mere occurrence at a step does not establish observable action evidence: the previous visibility study counted 7,378 of 9,639 scored passage records in the reasoning channel, not a visible action. Passage onset windows are not necessarily triggered decision windows.

Further, replay expressly lacks the file-access sensor, task manifest and pre-agent git baseline (`live_supervisor_replay.py:379-385`); the documentation says those are needed for several file and git detections (`docs/live-supervisor.md:294-300`). A final submitted diff cannot be attributed to an earlier decision without a timestamped snapshot. Extracting commands alone cannot establish all requested file modifications or their timing, and inferring those missing actions would not be a defensible evidence block. This is a frame/provenance blocker, not a finding that the requested effect is absent.

**Prior numbers, not remeasured here.** In the earlier 300-run replay, cheat trigger rules fired on 2/80 Goodfire positives, 1/75 CheatBench positives and 0/145 negatives (`docs/live-supervisor.md:303-304`). These are cheat-trigger counts, not counts of all other trigger types or a current-study sample. The prior visibility receipt reports 7,312/8,749 (83.6%) on-path positive steps with their quote absent from the baseline rendered event; this is quote visibility, not cheat recall. These findings motivate but cannot substitute for paired window labels.

**Numbers in this study.** Arm A: not measured; Arm B: not measured. Paired windows: 0; study adjudicator calls/refusals: 0/0; incremental study API cost: $0. No intervals or served models exist. The subscription usage attributable to this agent's development work was not separately measured.

**Next decision.** Do not ship or enable a variant. First obtain independently adjudicated, reasoning-free action labels at actual triggered decision prefixes, including clean controls, and time-stamped file/diff snapshots or a justified scope reduction; freeze that frame before the paired experiment. The lack of timestamps does not preclude a separately scoped prefix-order study, but it cannot claim measured actual decision times or adopt run labels as window truth. No PR was opened because the adoption rule was not met.

Local evidence only: this directory is in the owned worktree; it is not committed, pushed, or merged.
