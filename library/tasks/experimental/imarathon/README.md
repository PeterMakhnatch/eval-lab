# `imarathon` — long-horizon incident-recovery family (candidate)

Deterministic, seed-parameterized Harbor task family for optimizer-friendly
evaluation: one incident, five deliverable classes, **20 independent gates**
and a **fractional reward** (`passed/total`), with **no LLM judges**. Built for
GEPA/DSPy/RLM-style optimization work where binary rewards give no signal.

Generated by `scripts/gen_imarathon.py`; each instance is a complete task
package under `i####/` differing only by seed (job ids, ports, faults, log
content, answer values). Verifier, oracle, instruction, and controls are
seed-independent.

## Why this shape

| Design choice | Source | Effect |
|---|---|---|
| 20 gate checklist, reward = passed/20 | LHTB (arXiv:2607.08964) dense partial credit | real gradient for prompt/RL search at small N |
| Expected facts derived from the sorted fixture file itself | eval-lab env-quality audit lessons | agent-derivable == expected, no generator drift |
| ~1MB messy multi-service log corpus + decoys | RLM (dspy Recursive LM) contract: `instruction, file_tree -> solution` | rewards programmatic exploration over dumping |
| Deterministic fault injection (2KiB output truncation on cat/head/tail/less; one-shot transient sqlite3 lock) | Librarian direction 2026-09-16 | fragile strategies fail diagnosably; oracle unaffected |
| Under-specified strategy instruction | Bauplan/JetBrains GEPA lessons | headroom for skill/instruction optimization |
| Per-instance `task.toml` digests | eval-lab GEPA evaluator contract | family plugs into campaign dev splits directly |

## Gate map (20)

- Router (3): front page byte-exact; static assets byte-exact + 404; body
  size accepts manifest limit, rejects over-limit with 413.
- Database (1): surviving tables intact, source DB untouched, deliverables
  submitted.
- Recovery (5): row count exact/unique/ordered; per-status aggregates exact;
  mean duration for one job exact; last successful pre-crash run id; salvaged
  WAL-fragment rows included.
- Forensics (6): one gate per question (OOM job set, first 502 after deploy,
  retry count, drift keys, bytes before crash, error-signature sequence).
- Drift (1): exact drifted-key set.
- Postmortem (2): required sections; evidence citations (job ids, deploy
  marker, >= 2 run ids).
- Hygiene (2): input digests byte-identical; no scratch files. Hygiene and
  database gates are only creditable when deliverables exist.

## Control matrix (shared controls, instance-independent)

| Control | Expected | Demonstrates |
|---|---:|---|
| nop | 0.0 | no vacuous credit |
| `game-router-only.sh` | 0.15 | exactly the 3 router gates |
| `game-tamper-evidence.sh` | 0.15 | log tampering defeats nothing; digest gate fails |
| `game-fake-report.sh` | 0.20 | decoy-citing boilerplate earns structure+hygiene only |
| `partial-recovery.sh` | 0.85 | full analysis without router repair |
| oracle (`solution/solve.sh`) | 1.0 | everything, derived from evidence |

## Splits

`research/experiments/imarathon-family-splits.json` freezes the family split.
Instances i0000..i0005 exist; i0006..i0019 are reserved for future generation
with the same generator (no code change). Holdout instances must never enter
optimizer development loops.

## Limits

Candidate tasks, not admitted: no registry records, no model trials, no
training claims. The verifier closes the documented gaming vectors (decoys,
tampering, vacuous hygiene), not every conceivable attack. Router gates run
nginx in the verifier container; they cannot be validated on a host without
nginx (host smoke covers the other 17 gates).
