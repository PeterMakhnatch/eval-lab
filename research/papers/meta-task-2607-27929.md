# Meta-Task (arXiv 2607.27929) — analysis and lab mapping

Pan et al., USTC + Meituan, 2026-07-30. "Turning Terminal Task Synthesis
into a Terminal Task for Scalable Agent Training." Directly relevant: it is
the published version of this lab's authoring plane, built ON OUR STACK
(Harbor adapted for scheduling; Claude Code as generation scaffold;
Terminus-2 for trajectory sampling; exemplar pool synthesized by Claude
Opus and manually verified).

## Recipe (faithful)

1. **Meta-task = task synthesis packaged as a Terminal-Bench task.** The
   generator agent runs inside a Docker container; the meta-task's own
   test script is an automated completeness checker for the generated
   package. Self-validation loop: execute solution, run tests, check
   cross-component consistency and answer leakage, iterate until green.
2. **Instruction = fixed + variable.** Fixed: synthesis workflow, output
   format, Dockerfile/test best practices, self-validation checklist.
   Variable: 3 orthogonal dimensions — category (39 domain templates),
   scenario (10 instruction styles: minimal…emergency), difficulty (4
   levels w/ anti-pattern lists) = 1,560 base combos. Multi-phase mode:
   a lightweight meta-task first *designs* new (category, scenario) specs
   from ~2,000 topic seeds × ~120 style constraints → >240k combinations.
3. **Environment:** task skeleton (generation as structured content-
   filling), one sampled exemplar from a 100-task verified pool, optional
   GitHub/HF search-and-download tool for real materials.
4. **Filtering:** completeness checker → teacher samples solution
   trajectories → execution filter (must pass tests) → trajectory-level
   LLM-judge (removes leakage hints, trivially short runs).
5. **Numbers:** ~15,000 task packages, >85% synthesis success; 14,040
   sampled trajectories → 3,221 final SFT trajectories; SFT on those:
   Qwen3-14B 22.5% / Qwen3-32B 31.8% Avg Pass@1 on Terminal-Bench 2.0,
   beating TerminalTraj/TermiGen/Nemotron-Terminal/CLI-Gym/SkillSynth
   with far less data. Their comparison table: Meta-Task uniquely
   execution-grounded + scaffold-compatible + diversity-controlled.

## Mapping to this lab

| Meta-Task element | Lab equivalent | Verdict |
|---|---|---|
| Generation inside container w/ self-validation | authoring pipeline (battery post-hoc) | **ADOPT the pattern**: run `author propose` AS a Harbor task through our own queue — generation gets sandboxing, quotas, GATE, and generation *trajectories* become CRAFT-analyzable data |
| Dimension-decoupled spec sampling | CraftRecord facet space + craft-gap seeds | Ours is coverage-driven (targets unexercised facets) vs their random sampling — keep ours, add their topic-seed breadth |
| Skeleton + exemplar-in-env | not present | **ADOPT** — cheap, proven (>85% success) |
| LLM-judge trajectory filter | battery: oracle/nop/fair-oracle/adversarial + calibrated judges + human registry | Ours is stronger QC (their filter has no adversarial gate, no fair-oracle, no calibration); keep ours |
| Contamination handling | contamination fields (TaskVersion) | absent in paper — our edge |
| Statistical reporting | TRUTH refuse-to-rank | absent in paper — our edge |
| Goal: SFT data at scale | S3 of path-forward (export seam) | same supply chain; they prove the SFT payoff end-to-end |
