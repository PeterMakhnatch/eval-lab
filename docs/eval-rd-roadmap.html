EVAL LAB / HARDENING ROADMAP
Repository state R&D roadmap Agent workflow Scaling gates

Opinionated plan · 2026-08-14 · Harbor 0.21.0

Build a trustworthy eval factory.

Keep Harbor as the execution engine. Harden this repository into the control plane that qualifies benchmarks, authenticates many agent CLIs, preregisters experiments, executes bounded matrices, separates invalid runs from capability results, and turns evidence into reviewable follow-up work around the clock.

Deliberately out of scope: RL environments, weight updates, post-training pipelines, custom model serving, and replacing Harbor.

My recommendation

Pause horizontal feature growth. Finish one trustworthy vertical path from agent credential → qualified task → controlled experiment → valid trial → statistics → eval card → bounded next proposal.

Then widen that same path across agents and benchmarks.

The factory is not “agents running random benchmarks all night.” It is a closed, inspectable pipeline in which every stage produces a typed artifact and the executor is the only component allowed to spend money or start Harbor.

Phase 0 — repair before expanding

These are release blockers for a 24/7 loop. They are not polish: each currently allows a green-looking system to produce unusable or misleading research.

P0.1

Make CI represent the repo

Move dashboard, calibration, and analysis tests into an explicit CI test matrix; repair the ten migrated-path/stale-fixture failures; add coverage for every CLI command that can dispatch, classify, or publish a result. Keep benchmark-container tests separate.

P0.2

Add one composed smoke contract

Create make smoke around a free task: submit → policy → Harbor → verifier → immutable job → PostgreSQL → Parquet → summary. Run it on every dependency or Harbor upgrade and on a scheduled local health cycle.

P0.3

Fix authentication at the boundary

An auth preflight must exercise the same credential-injection path as the real Harbor run, then abort after the first repeated 401. A trial without an assistant turn, token record, or agent artifact is invalid—not reward zero.

P0.4

Repair comparison and judgment

Fix stale evidence roots, freeze the judge input contract, repair the three criteria responsible for most calibration disagreements, and refuse judged metrics below their recorded agreement floor.

P0.5

Make evidence durable before prose

Researcher output may cite only promoted, content-hashed evidence. Validate link existence, digest, trial IDs, denominator, selection rule, and fixed task/verifier digests before appending a discovery or generating a runnable proposal.

P0.6

Choose one worktree state model

PostgreSQL is shared while Parquet is currently worktree-local. Choose shared derived storage, isolated catalogs, or evidence-root-scoped invariants so two agents cannot observe contradictory system health.

Exit gate: one free control and one paid canary complete through the same queue, produce valid trajectories, land in both derived stores, appear in a comparison, and generate an eval card with no manual file repair.

Phase 4 — scale the proven path

“Good scale” should mean predictable throughput with intact experiment semantics. Increase concurrency only after invalid-run rate, cost waste, recovery, and evidence integrity are measured.

scheduler

Leases, heartbeats, idempotency

Give each dispatch an immutable key, worker lease, heartbeat, cancellation path, and reconciliation logic. Infrastructure retries remain distinct from stochastic attempts.

capacity

Two-dimensional concurrency

Limit both environment slots and per-agent/provider calls. Add weighted scheduling by estimated CPU, memory, duration, dollars, and provider quota instead of one global concurrency number.

storage

Content-addressed evidence

Keep local raw jobs while one workstation is enough. Add S3-compatible immutable objects before adding remote workers or a second analyst; verify uploads before cataloging them complete.

data

Incremental, rebuildable derivatives

Use checkpointed ingestion and projection keyed by raw evidence digest. PostgreSQL owns lineage and queue state; Parquet/DuckDB own analytical scans. Do not add ClickHouse without measured event volume and latency pressure.

observability

Research and operations telemetry

Track queue age, worker utilization, auth/install/harness failure rate, invalid-trial percentage, ingestion lag, bytes, query latency, spend, cost per valid trial, and proposal acceptance rate.

reproducibility

Pin the whole execution identity

Record Harbor, agent CLI, task, verifier, image, model, profile, prompt/preamble, tool policy, environment, and lab commit. A changed pin creates a new cohort.

Phase 5 — the bounded 24/7 factory

Autonomy should expand by evidence class, not by giving a general agent more shell access. The safe loop is mostly deterministic orchestration with read-only reasoning agents at narrow decision points.

Recommended implementation sequence

These are dependency-ordered capability gates, not calendar promises. Do not start the next stage merely because code exists; require the acceptance evidence.

  1. Green means green. Repair excluded tests, add the composed control smoke, and make invalid trial classification part of ingestion. Acceptance: the full repository-owned suite is green and an injected auth failure cannot become a score.
  2. Prove Codex and Claude as profiles. Unify their credential injection and headless doctor behavior. Acceptance: one valid canary each, or an honest credential deferral with zero launched trials.
  3. Add Gemini and Grok through the generic profile contract. No executor special cases. Acceptance: install, preflight, tiny paid smoke, and canary evidence for each under separate limits.
  4. Ship experiment registry + statistics + eval cards. Acceptance: rerunning a frozen spec reproduces cohort membership and the generated card accounts for every planned, invalid, missing, and valid attempt.
  5. Ship the candidate-task foundry. Acceptance: an agent-generated task cannot become registered without provenance, build, controls, adversarial qualification, and review.
  6. Restart the researcher loop on trustworthy inputs. Acceptance: every discovery link resolves in a clean checkout, every denominator is explicit, proposals preserve digests, and no reasoning agent can execute.
  7. Measure before distributing. Add object storage or remote workers only when local durability, queue wait, resource saturation, or collaboration metrics cross a recorded threshold.

What I would not build yet

not now

RL / post-training

It depends on trusted tasks, rewards, cohorts, and trajectories. None of the immediate hardening work requires it.

not now

Another eval harness

Harbor is already broad enough. The current failures are in integration, evidence validity, and methodology rather than missing execution adapters.

not now

Kubernetes by default

Start with measured local bottlenecks. Remote workers add secret, evidence, retry, and reconciliation complexity before they add research quality.

not now

ClickHouse

PostgreSQL plus Parquet/DuckDB is appropriate until event volume or concurrent query latency provides a concrete reason to add a serving database.

not now

Vector memory

Similarity search becomes useful after there is a substantial corpus of accepted, durable analysis sidecars. It cannot repair bad evidence contracts.

not now

Write-heavy dashboard

Keep approval and policy mutations behind audited CLI/file contracts until the state machine is stable. The dashboard should remain a read surface.

Definition of “factory ready”

  • Four independently authenticated agent profiles pass canaries.
  • Every capability score excludes and reports invalid trials.
  • Every study is reproducible from immutable digests.
  • Every comparison reports n, pairing, interval, and missingness.
  • Every judged dimension names a current calibration record.
  • Every registered task passed controls and adversarial review.
  • Every discovery resolves its evidence in a clean checkout.
  • Every automatic dollar maps to a committed policy rule.
  • Crashes, expired credentials, and rate limits recover without duplicate work.
  • The daily digest explains what ran, what failed, what was learned, and what waits.
