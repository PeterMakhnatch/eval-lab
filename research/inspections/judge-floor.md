## Why the low criteria are not yet clean model evidence

The repository currently contains two incompatible calibration contracts. The family README says to place each postmortem beside the family's unchanged evidence directory and run the existing rubrics; those original rubrics explicitly ask whether facts, files, metrics, and invented specifics do or do not appear in `/app/evidence` ([README contract](../calibration/README.md#L40-L48), [causal rubric](/Users/petermakhnatch/Developer/agent-evals/harbor-practice/datasets/judged-output/checkout-pool-exhaustion/tests/causal_reasoning/judge.toml), [action rubric](/Users/petermakhnatch/Developer/agent-evals/harbor-practice/datasets/judged-output/checkout-pool-exhaustion/tests/action_quality/judge.toml), [evidence-fidelity rubric](/Users/petermakhnatch/Developer/agent-evals/harbor-practice/datasets/judged-output/checkout-pool-exhaustion/tests/evidence_fidelity/contradictions.toml)). The later brief and implementation instead specify documents plus named criteria and reference facts, and the generated environment copies only `documents/` and `rubric.json` ([brief-09 contract](../../docs/prompts/09-judge-calibration-dspy.md#L7-L18), [staging implementation](../../src/evallab/calibrate.py#L544-L611), [seven checkout facts](../../src/evallab/calibrate.py#L65-L75)).

That difference matters most for the observed cluster. For example, a sealed key can say `invents_evidence=no` because cited details appear in `/app/evidence`, while the staged judge has no complete artifact inventory against which to check that assertion ([example key](../calibration/checkout-pool-exhaustion/answer-keys/10-correct-timeline-dense.json#L54-L70), [staged instruction](../../src/evallab/calibrate.py#L604-L611)). The committed calibration record also points to a prediction artifact under `runs/` that is absent from a clean checkout, so the report is sufficient for criterion totals but not for a durable document-level confusion audit ([prediction path](../calibration/records/checkout-pool-exhaustion/checkout-pool-exhaustion-20260814-gpt-5-6-sol-bbfcdacbd3.json#L83-L92), [ignored run policy](../../.gitignore#L18-L23)).

## Repair target and decision boundary

“Repair specific criteria” means first selecting one authoritative input contract, then making `invents_evidence`, `asserts_unsupported_cause`, and `proposes_unsupported_work` decidable from that input without relying on missing files; preserve the sealed labels and rerun the identical 22-document corpus afterward ([corpus manifest](../calibration/checkout-pool-exhaustion/corpus.json), [append-only record contract](../../docs/prompts/09-judge-calibration-dspy.md#L20-L31)). Secondary subfloor criteria should be inspected after that rerun rather than simultaneously rewritten, because the current record does not isolate rubric wording from missing evidence.

Do not start DSPy from this measurement: the existing dry-run does preserve a six-document holdout, but optimizing a prompt against labels whose required evidence is absent can reward fixture- or wording-specific shortcuts rather than the intended evidence judgment ([DSPy dry-run record](../calibration/records/dspy-checkout-dry-run-20260814.json)). Do not wait for Claude as the next action: its credential is merely pending, and the same current staging path would preserve the input-contract confound ([pending backend](../calibration/records/checkout-pool-exhaustion/checkout-pool-exhaustion-20260814-gpt-5-6-sol-bbfcdacbd3.json#L89-L92), [shared backend staging](../../src/evallab/calibrate.py#L544-L568)).

This conclusion is scoped to one family, one model/backend tuple, one 22-document corpus, and one run. It supports criterion repair for this calibration gate; it does not estimate Codex-as-judge quality across families or tasks ([record scope](../calibration/records/checkout-pool-exhaustion/checkout-pool-exhaustion-20260814-gpt-5-6-sol-bbfcdacbd3.json#L1-L10), [small-sample discipline](../../docs/analysis-loop.md#stage-4-deterministic-comparison)).
