## Why the repaired grader rejected the reference oracle

TS-14 measured the first repair against the retained reference: **reward 0** (`.../native/pr-1343/repaired`). The base server creates the standalone parent (job 16, `Complete`, exit 1) but rejects the first dependent create:

```
POST /jobs/create HTTP/1.1 400 -
```

The guard is base behaviour (the reference patch never edits it), and it treats a missing batch as invalid for a dependent job. A standalone `Client.create_job(..., parent_ids=[...])` child therefore cannot be created at all, whether the parent is batchless or batch-scoped. ## Correction

The already-selected client test keeps its root-job acceptance and its standalone-parent assertion. The unreachable dependent-job block is replaced by an assertion on the **outgoing request document**, using the same monkeypatch pattern the file already uses in `test_api_create_job_sends_always_run_request_body`:

```python
client.create_job(..., parent_ids=[parent.id])                 # always_run omitted
client.create_job(..., parent_ids=[parent.id], always_run=True)

assert seen[0]['always_run'] is False
assert seen[1]['always_run'] is True
```

This targets the same default at the layer where it is observable: the mutant that flips the client default from `False` to `True` (QA key `line-fef1200c48`) now fails the first assertion. The default/`False` cancellation behaviour after a failed parent remains covered by the batch-scoped tests in the same patch (`test_default_child_cancelled_after_parent_error`, `test_always_run_false_child_cancelled_after_parent_error`).
