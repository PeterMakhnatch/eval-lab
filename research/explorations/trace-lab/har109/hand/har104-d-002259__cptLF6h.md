# har104-d-002259 — PHARE: MHD population in `populateDict` (reward 0.0)

## What the task asked

Teach `pyphare.pharein.populateDict` to handle simulations whose `model_options` include `MHDModel`. For `eta=0.1, nu=0.01, gamma=2.0, hyper_mode="constant"` it should write the MHD algorithm values, an `mhd_state` entry with its conservative-init gamma, the 8 dimension-appropriate initializers from `MHDModel`, and `default` MHD tagging under AMR tagging. Only for `MHDModel`. Leave the Hybrid path alone.

Hidden tests use a dictator spy and check far more: an exact 2D entry table, `Simulator.setup()` ordering, Hybrid isolation, two `RuntimeError`s, `clearDict` idempotency, session isolation, and 100 repeat cycles.

## Why it failed

The model never wrote any code. 90 episodes and 126 shell calls produced zero file changes, so the verifier saw the base repo and scored 0. It burned 2.37M input tokens catting large C++ headers in 9 minutes until the proxy refused the next model call.

## Who is to blame

The model. The harness executed every command and returned output. The environment was fine. The task's hidden lifecycle contract is unfair, but this run failed before that mattered: it never attempted even the stated core population.

## Is the task fair?

No. The core population is described, but none of the lifecycle and error contract is: the two `RuntimeError`s, `clearDict` idempotency, session isolation, exact dict paths, and per-dimension initializer arity. That is the heaviest discovery load in the set. A run with a correct narrow fix still fails hidden tests, so the task is broken, and too hard for this model class.
