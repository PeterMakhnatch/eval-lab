## Capability incident, audit and containment

The13th invocation contained an actual successful stateful tool event and two assistant turns. Both assistant turns named the requested native route, but the frozen parser rejected the multi-turn envelope. The stored conservative classification `model_attestation_unknown` must not be misread as an observed model fallback or exhausted quota. Post-return rejection cannot undo a handler that already ran.

The newly created managed file was815 bytes. Exact bytes, SHA256 and creation/stat/event evidence were preserved privately, without printing/interpreting/following the body. Parent then used the official exact-record deletion. At **1:13:05 PM ET** the active file and its new directory were absent and the private byte-copy SHA still matched. Exposure began **12:23:52 PM ET**; the bounded exposure window is about49m14s. Other-session consumption was not audited and is not claimed zero. No user-authored skill, unrelated data, profile or global OMP source/configuration was changed by this worker.

The completed owned retained-event census covers **163 streams,164 assistant turns,141,081,176 bytes**:74 Sonnet,74 Opus,15 Luna streams. It found exactly **one tool start/end and successful handler**, the known contained incident; all other retained streams had zero observed tool events. Zero malformed JSON, missing final agent ends or turn-count mismatches. This is not proof that zero tools were offered/callable, and it does not cover other chats or unretained actions. The separate METR79 invocations did not retain raw streams: actual tool-event counts there are **UNKNOWN**, not inferred zero from their parser.

Public tag18.12.6 wiring is compatible with `--no-tools` emptying requested names while an enabled top-level autolearn tool is independently included. The installed binary's exact build/dispatch registry was not independently attested. **The required empty-dispatch/zero-offered-tools boundary is not established.** The forward admission gate forbids all generation; its synthetic test proves no transport/handler/side effect occurs because launch is denied. That is deliberately **not** presented as an offline proof that OMP would reject an unsolicited tool call after launch. Future inference requires a separately reviewed hard-deny/empty-dispatch implementation plus zero advertised tools and an offline unsolicited-call/no-side-effect proof, or an explicitly approved separately named transport proposal—not another flag, prompt, post-event kill or policy workaround.
