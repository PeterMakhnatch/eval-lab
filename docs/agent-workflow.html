The protocol makes sense. The status layer needs a reset.

The agent system uses repository files, isolated Git worktrees, exclusive write scopes, handoffs, and current-head CI to coordinate parallel work. That is a coherent model. The first wave also exposed where the written protocol and the actual post-merge state diverge.

About “.fd files”

There are no .fd files in this repository. You likely meant the Markdown .md files such as AGENTS.md, WORKFLOW.md, and the handoffs. Those are the agent-facing control documents.

What the agent structure gets right

clear isolation

One writer per tree

Shared filesystem access is made safe through distinct worktrees and explicit writing ownership rather than optimistic coordination.

durable context

The repository is the record

Sessions may disappear, but commits, handoffs, queue events, runs, and reports remain inspectable.

fail closed

Authority is encoded

Cost and run permissions live in policy and queue transitions, not in a prompt asking an agent to behave.

reviewable

Small role-shaped PRs

Role-prefixed titles and narrow owned paths make the integration queue understandable to a human reviewer.

precise gate

Exact-head CI

The workflow learned not to treat an old green run or local success as permission to merge.

sensible escalation

Agents stop on foreign conflicts

This prevents a role from “solving” an integration conflict by silently changing another role's work.

Where the protocol and reality disagree

state disagreement

ROLES says done; handoffs do not

The role table says the wave is fully sunset, while 11 handoffs report a non-done legacy status and four more lack the machine-readable header entirely. fleet-status.sh can therefore render misleading blockers even when no role branch exists.

ownership overlap

“Exclusive” is not always exclusive

BUILDER owns all of src/, while ANALYST, OBSERVER, AUTOPILOT, and JUDGE also own named files inside src/. That was workable for a wave, but it is not a timeless ownership model.

missing command

Fleet design is unfinished

Documentation references evallab fleet, evallab report, and generated diagrams, but the CLI still relies on scripts/fleet-status.sh. The script works; the promised unified command does not exist.

ephemeral evidence

Ignored paths leaked into durable prose

The first researcher pass appended links into ignored queue/ state. Worktree cleanup then made those citations nonportable. Promotion must happen before journal append.

shared-state ambiguity

Worktrees isolate code, not every service

PostgreSQL is shared while Parquet defaults inside each worktree. A fresh role can therefore fail a global catalog/projection invariant even when its own work is correct.

historical drift

Old guidance still reads as current

The operating manual, engineering open-items section, README, and some briefs contain claims superseded by later inspections or fixes. Agents need an explicit “current vs historical” convention.

A simpler agent model for the next wave

  1. Make one source canonical for live fleet status. When a role is sunset, either archive its handoff or rewrite its header to Status: done. The fleet renderer should ignore historical blockers when the registry says the role is retired and no branch exists.
  2. Separate persistent ownership from mission grants. Let BUILDER own application code by default; record temporary file-level grants in the mission or a wave manifest instead of keeping overlapping “exclusive” ownership forever.
  3. Add a machine-checkable closeout command. It should verify: no active worktree, no open PR, role marked done, handoff marked done, branch retired, and all durable links resolvable.
  4. Make evidence promotion part of completion. A report cannot cite queue/, runs/, or a role worktree unless the cited artifact is copied into reviewed evidence or replaced with a committed aggregate.
  5. Finish or retire the fleet brief. Either implement evallab fleet/report and generated diagrams, or update the docs to bless the shell script as the final interface. Avoid two promised operating surfaces.
  6. Label historical documents. Add a visible “superseded by” banner to old checkpoints, briefs, and handoff bodies rather than allowing future agents to treat every Markdown sentence as current truth.
